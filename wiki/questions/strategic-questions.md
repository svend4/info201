# Стратегические вопросы и варианты ответов

## 1. Что является ядром экосистемы?
**Вопрос:** Info OS — это операционная оболочка, база знаний, оркестратор агентов или методология?

**Варианты ответа:**
- Ядро = граф знаний + динамические блоки; агенты и приложения являются плагинами.
- Ядро = агентная платформа; граф/поиск/документы являются инструментами агентов.
- Ядро = энциклопедия методик; кодовые репозитории являются демонстрациями.

**Рекомендация:** выбрать первый вариант как наиболее объединяющий: он позволяет включить RAG, документы, магазины, медицину, право и игры как доменные слои.

## 2. Какие репозитории нужно слить первыми?
**Вопрос:** С чего начать монорепозиторий, чтобы не потерять идеи?

**Варианты ответа:**
- `info40` + `info100` + `infom`: агентная лаборатория и граф-RAG.
- `ingit` + `daten20` + `universal-file-storage-mcp`: документация, версии, файловое хранилище.
- `info10` + `daten2` + `meta4`: commerce/flower-shop как прикладной демо-домен.

**Рекомендация:** начать с документационно-поискового ядра (`ingit`, `daten20`, `infom`) и затем подключать агентный слой (`info40`, `info100`).

## 3. Как доказать практическую ценность?
**Вопрос:** Какой демо-сценарий должен быть главным?

**Варианты ответа:**
- Локальная энциклопедия профиля: индексирует все репозитории, строит связи, отвечает на вопросы.
- Агентный менеджер задач: берёт идею из wiki, создаёт issue/план/патч.
- Доменное приложение: магазин цветов или социально-юридический помощник.

**Рекомендация:** локальная энциклопедия профиля — самый естественный первый MVP, потому что она использует уже существующий материал.

## 4. Какие инновационные комбинации наиболее перспективны?
- **GraphRAG + InGit + MCP storage:** репозитории становятся живой базой знаний с версионированными документами и доступом из AI-клиентов.
- **Agent orchestration + dynamic blocks:** агенты не просто пишут текст, а собирают объяснимые блоки решений.
- **Flower shop + multi-agent simulation:** магазин становится симулятором спроса, логистики, персонализации и переговоров.
- **Medical/legal templates + provenance:** каждая рекомендация должна ссылаться на источник, версию шаблона и уровень уверенности.
- **MMO/professional simulator + TSP/optimization:** игровые сценарии становятся тестовой средой для алгоритмов планирования.

## 5. Как классифицировать каждый проект?
Использовать поля:
- `status`: idea / sketch / prototype / demo / product / archive
- `role`: app / package / service / dataset / documentation / experiment
- `domain`: core / AI / docs / commerce / social / med / robotics / games / devtools
- `dependencies`: какие репозитории нужны для запуска
- `merge_target`: куда проект попадёт в монорепозитории
- `next_action`: одно действие на 30–90 минут
